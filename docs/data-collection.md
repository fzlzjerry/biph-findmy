# 「描述物品」数据采集活动 · Describe-an-object activity

**Owner: Data Science Club.** This activity gives the matching engine its first *real* test set.
The synthetic numbers in [eval_report.md](eval_report.md) are generated by our own templates, so they
flatter the model. The real-data result is the honest number for the Q1 presentation.

匹配引擎目前只在合成数据上测过，那些数据是我们自己的模板生成的，结果偏乐观。这次活动采集的真实描述才是 Q1 展示里最可信的数字。

---

## 准备 · Before the activity (about 45 minutes, 6–10 people)

1. **约 30 件真实物品**。可以借社团成员的东西，或者经前台同意，用失物招领箱里的物品。一定要有**长得很像的几组**，这部分最能说明匹配引擎的价值：
   - 3–5 个黑色水杯（一个有贴纸、一个有凹痕、一个什么特征都没有……）
   - 2–3 个 AirPods 盒
   - 2–3 件深蓝色卫衣或外套
   - 2 个计算器、几个笔袋、一把伞、一副眼镜……
2. 每件物品贴一张编号便签（`A01`–`A30`），描述的时候不要把编号写进去。
3. 准备一张共享表格（Google Sheets、腾讯文档或 Excel 都可以），表头用下面的 [CSV 格式](#csv-格式--format)。

## 怎么写 · How to write the descriptions

每件物品要两个人来写，**两个人不能看对方写的内容**：

| 角色 | 怎么写 | 例子 |
|---|---|---|
| **失主 Owner**（丢失描述 `lost`） | 由用过这件东西的人写，**不看实物**，凭记忆写，就像真的丢了东西去网站上发帖：大概在哪里丢的、什么时候、长什么样。 | 「我的黑色保温杯不见了😭 上面贴了个恐龙贴纸，周二体育课之后在体育馆」 |
| **捡到者 Finder**（捡到描述 `found`） | 由另一个人写，**看着实物**，就像在走廊捡到了这件东西：是什么、在哪里捡到的（自己设定一个合理的地点）、能看到的细节。可以加一条只有失主才知道的「私密细节」，比如里面装了什么、底部的划痕。 | `Black thermos, green dinosaur sticker, found on the gym bleachers` |

- **怎么自然就怎么写**：中文、英文、中英混写都可以，网络用语、错别字、繁体字也都可以。不要刻意写得很工整，真实的帖子本来就不工整。
- 同一件物品最好有 2 个不同的人写「捡到描述」。每件物品 1 条丢失描述加 1–2 条捡到描述，30 件物品就有 60–90 条。
- 时间：日期填活动当天或前几天。丢失描述可以写一个时间段（`window_hours`），比如「中午到下午三点之间」就是 3。
- **不要写真实的个人信息**：不写真名、电话、学号。需要名字缩写时就编一个（比如 `K.L.`），这样数据可以放心存进仓库。

## CSV 格式 · Format

保存为 UTF-8 编码的 `matcher/data/real_pairs.csv`，第一行是表头：

```csv
object_id,kind,text,date,time,window_hours,places,colors,category,private_detail
A01,lost,"我的黑色保温杯不见了 上面贴了个恐龙贴纸，周二体育课之后",2026-10-20,14:30,2,lower_gym,black,water_bottle,
A01,found,"Black thermos, green dinosaur sticker, gym bleachers",2026-10-20,16:00,,lower_gym,black;green,water_bottle,lid says K.L.
A02,lost,"white airpods case with a cat sticker, lost it somewhere near the lockers",2026-10-21,,4,a_1f;b_2f,white,earbuds,
```

| 列 | 必填 | 说明 |
|---|---|---|
| `object_id` | ✓ | 物品编号。同一件物品的丢失描述和捡到描述用同一个编号，系统靠它判断哪两条是真匹配。 |
| `kind` | ✓ | `lost` 或 `found` |
| `text` | ✓ | 描述原文，包含逗号时用英文双引号括起来 |
| `date` | ✓ | `YYYY-MM-DD`，按北京时间 |
| `time` | | `HH:MM`，不填默认中午 12:00 |
| `window_hours` | | 只用于 `lost`：可能丢失的时间段有几个小时 |
| `places` | | 地点 ID，多个地点用 `;` 分隔（见下表） |
| `colors` | | 颜色 ID，多个用 `;` 分隔 |
| `category` | | 类别 ID（见下表） |
| `private_detail` | | 只用于 `found`：只有失主才知道的细节 |

`places`、`colors`、`category` 这三列模拟的是网站上用户确认过的标签，不确定的话可以留空，让 NLP 自己从描述里抽取。

## 跑评估 · Run the evaluation

```bash
uv run python -m matcher.eval.run      # 重新生成 docs/eval_report.md 和图表
```

报告里会多出一节 **Real**，列出 R@1、R@3、MRR，以及和两个 baseline 的对比。

- 真实数据**只用来测试，不参与训练**：权重是在合成数据上拟合的，真实数据从来没被模型见过，所以测出来的数字是诚实的。
- 只有 30 件物品时，置信区间会比较宽，报告里会如实写出来。在 Q1 展示里，这本身就是一个值得讲的点：数据越多结论越可靠。下学期可以把网站上真实的「是我的 / 不是我的」反馈也纳入进来。

## 隐私 · Privacy

- 参加活动的同学要知道这些描述会存进社团的代码仓库（私有），并用于评估和展示。
- 描述里不出现真实姓名、电话、学号、证件照片。
- 学生卡、银行卡这类敏感物品可以写描述，但不要拍照。
